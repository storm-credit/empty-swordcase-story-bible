## 2. 왜 기존 ‘200화 완료’ 판정이 혼란스러웠는가

저장소의 최초 정의는 다음 네 층위를 구분했다.

1. **Architecture**: 5 Act / 20 Subact / 200 Episode coverage
2. **Production Blueprint**: 회차별 구체 씬비트
3. **Draft**: 소설 원고
4. **Revision**: 문체·연속성·상업성 교정

초기 `data/project_manifest.json`은 다음을 명시한다.

- 1~200화 기능 지도: 완료
- 1~20화 상세 씬비트: 완료
- 21~200화 상세 씬비트: 미완료

이후 `data/episodes_*.json`이 200화를 모두 덮으면서 목표·선택·보상·훅·비용이 채워졌고, 후속 문서가 이를 ‘200화 설계 완료’로 표현했다. 그러나 `CLAUDE.md`의 집필 가능 게이트는 한 화마다 **6~10개 씬비트**를 요구한다.

21~40화 제작 패킷은 회차당 네 개의 장면 비트와 대가·훅을 가지므로 요약 제작 패킷으로는 유효하지만 최종 집필 패킷에는 미달한다. 41~200화 데이터는 회차 기능표이며 장면 패킷은 아니다.

따라서 앞으로 다음 표현만 사용한다.

> **200화 아키텍처와 기능 지도 완료 / 1~20화 상세 설계 완료 / 21~40화 부분 상세화 / 41~200화 상세 씬비트 미완성.**

## 3. 세계관 감사

### 3.1 8권역

`data/world_regions_008.json`은 각 권역에 다음을 둔다.

- 주식과 결핍
- 이동 수단과 병목
- 생활 금기와 소유 관습
- 평시 일정과 재난 취약점
- 감각 표식과 지역 어휘
- 비합리적 규칙
- 결말 기여

권역 단위 설계는 완료로 판정한다.

### 3.2 48거점의 실제 문제

기존 `data/world_settlements_048.json`은 48개의 이름·회차·랜드마크를 가진다. 그러나 같은 권역 안의 여섯 거점은 다음 필드를 동일하게 반복한다.

- `current_tension`
- `entry_rule`
- `daily_operation`
- `logistics_bottleneck`
- `disaster_weakness`
- `sensory_marks`
- `local_terms`

즉 기존 상태는 **48개의 장소 이름과 사건 씨앗 / 8개의 운영 템플릿**에 가깝다.

v3.3에서는 `data/settlement_identity_overlay_v3_3.json`을 추가해 모든 거점에 다음을 개별 지정했다.

- 고유 생활·행정 기능
- 지역 단위 병목
- 반복 가능한 일상 절차
- 거점 고유 소유권 분쟁
- 생활 흔적 증거
- 실패 시 다른 거점으로 이어지는 연쇄 손실
- 연결 노선과 주 세력

기존 거점명·회차·랜드마크는 변경하지 않았다.

### 3.3 20노선의 실제 문제

기존 `data/world_routes_020.json`은 다음 여섯 필드만 가진다.

- ID
- 출발지
- 도착지
- 회차
- 병목
- 대가

이는 이동 경로 표로는 충분하지만 경제·전쟁·재난을 움직이는 물류망으로는 부족하다.

v3.3의 `data/route_operability_overlay_v3_3.json`에는 다음을 추가했다.

- 통제 세력
- 정상 이동 시간
- 표준 처리량
- 폐쇄 조건
- 우회로
- 폐쇄 뒤 연쇄 손실
- 노선 고유 소유권 질문

### 3.4 18세력의 실제 문제

기존 세력 데이터는 독점 자원·외부 의존·수입원·고정비·공개 목표·생존 목표·강경파·온건파를 가지고 있어 개별 경제는 강하다.

그러나 세력 간 동맹·적대·지휘·거래·배신 조건을 직접 참조하는 관계 데이터가 없었다. 이 상태에서는 세력들이 담운의 회차에 맞춰 한 곳씩 등장할 뿐, 서로를 움직이는 정치 체계가 되기 어렵다.

v3.3의 `data/faction_relation_overlay_v3_3.json`은 다음을 추가한다.

- 18세력의 승리 조건
- 패배 조건
- 담운 부재 시 자율 행동
- 주 활동 거점
- 25개 세력 관계선
- 분쟁 자원
- 갈등 격화 조건
- 해결에 필요한 증거·협상 지렛대

## 4. 설계도 감사

### 4.1 5액트와 결말

다음은 변경하지 않는다.

- 담운은 과거 수장 이름 조각에서 태어났지만 별개의 인간이다.
- 담운은 자기 자신을 수집하지 않는다.
- 신수는 수집품이 아니며 계약을 거절·종료할 수 있다.
- 중앙 소유선을 반치로 자른다.
- 중앙 권한을 공동 지분으로만 바꾸지 않는다.
- 여섯 책임 조각을 권역에 배송한다.
- 권한이 아니라 책임을 분산한다.

대형 설계는 재작성할 필요가 없다.

### 4.2 20 Subact 인과의 실제 문제

기존 `data/acts_subacts_005_020.json`은 모든 Subact의 `causal_input`에 사실상 같은 문장을 반복한다.

> 앞 서브액트의 선택 비용을 다음 생활 문제로 넘긴다.

원칙은 옳지만 어떤 비용이 어떤 문제를 만드는지는 기계가 읽을 수 없고 작가도 즉시 사용할 수 없다.

v3.3의 `data/subact_causality_overlay_v3_3.json`은 각 Subact를 다음 필드로 연결한다.

- 이전 구간에서 넘어온 실제 손실
- 현재 생활·제도 문제
- 담운의 자발적 목표
- 되돌릴 수 없는 선택
- 다음 구간에 남기는 비용
- 다음 Subact ID

### 4.3 200화 상세화의 남은 범위

200화 전체에 목표·선택·보상·훅·비용이 있으므로 사건 골격을 새로 만드는 작업은 필요 없다.

남은 작업은 21~200화 각 화를 다음 수준으로 승격하는 것이다.

- 6~10개 씬비트
- 장면별 입장 상태
- 즉시 압력
- 실제 시도와 반응
- 포기하는 선택
- 장면 종료 시 몸·돈·장비·권리·관계 변화
- 다음 장면으로 이어지는 물리적 잔여

이는 새 플롯 작성이 아니라 기존 회차 기능표의 **Production Blueprint 승격**이다.

## 5. 설정집 감사

### 5.1 확인된 완성 영역

- 무주함 규칙
- 강탈품 거부
- 의흔의 한계
- 상극과 대가
- 귀환·공동 관리·비수집 진척
- 신수 비소유·철회권
- 주요 인물 변화선
- 8개 S-Tier 질문
- 20개 A-Tier 질문
- 핵심 아이템 장기 트랙 16개

### 5.2 수집품 120·세트 24·신수 18 판정

프로젝트 개요와 매니페스트는 수량을 선언하지만, 현재 정본 진입점과 매니페스트가 직접 참조하는 장기 아이템 트랙은 16개다.

따라서 다음을 구분한다.

- **수량 목표 선언:** 완료
- **핵심 아이템 장기 회수:** 16개 완료
- **120개 전부의 개별 ID·기능·제약·첫 등장·재사용·귀환·최종 상태:** 확인 불가
- **24세트 전부의 조합·상극·해체·중복 감사:** 미완료
- **18신수 전부의 계약 거절 조건·독립 목표·이탈·최종 상태:** 미완료

120·24·18이 실제로 별도 원천 파일에 존재한다면, 다음 v3.3 작업에서 그 파일을 정본 진입점에 명시하고 전수 검증기에 연결해야 한다. 존재하지 않는다면 ‘완료’가 아니라 ‘규모 목표’로 되돌린다.

## 7. 완료 기준

설정집·세계관·설계도를 최종 완성으로 승격하려면 다음을 모두 통과해야 한다.

1. 48거점 모두 고유 운영 기능과 연쇄 손실을 가진다.
2. 20노선 모두 처리량·폐쇄·우회·통제 세력을 가진다.
3. 18세력 모두 최소 두 관계선과 자율 행동을 가진다.
4. 20 Subact 모두 구체적인 이전 비용과 다음 비용이 연결된다.
5. 120수집품·24세트·18신수의 원천 파일과 전수 감사 결과가 존재한다.
6. 21~200화가 6~10개 씬비트 Production Blueprint로 승격된다.
7. 오래된 완료 선언과 최신 상태표가 충돌하지 않는다.
